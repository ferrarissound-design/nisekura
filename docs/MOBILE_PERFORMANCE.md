# JOCRAFT2 Phase 2 — スマホ描画性能

## 対象と測定環境

基準 main: `34ba2c8e79c1429682f06d073ac52a0c95588a07`（セーブ保護PR #13を含む）。iPhone 16 / A16 iPad / Safariを主要ターゲットとするが、今回の数値は **Node VM＋WebGLモック** による処理回数とCPUウォール時間。GPU描画、端末FPS、電力、発熱を測った数値ではない。60FPS / 高負荷30FPSの達成は未検証。

## 調査で確認した既存構造

- WebGL 1。近景はボクセルメッシュ＋共有16bit四角形インデックス。遠景は視錐台カリング付きLOD、Workerまたはフレーム分割生成。距離別植生、チャンク/LODキャッシュ上限あり。
- 雲は静的メッシュを時間差分で移動し、必要時に分割再生成。水・植物はシェーダーで動く。
- 全30種類の生き物は1本のモデルバッファを共有。既に画面外カリング、距離別AI更新、個体プール、自然発生数の負荷調整が存在した。
- タイトルは既にプレイヤー物理を停止していたが、描画・ストリーミングはrAFごと。タイトルの低FPSも自動解像度に反映されていた。
- エッグ画面は初回だけ構築されていたが、その初回に30種を同期生成。選択中のエッグ画像は別途キャッシュされていた。
- コンテキスト復旧で雲の座標/生成器をリセットせず、新しいGPUバッファがないまま再構築条件を満たさない可能性があった。WorkerのBlob URLも解放していなかった。

## 変更と維持するもの

| 変更 | 負荷が減る理由 | 維持するもの・トレードオフ |
| --- | --- | --- |
| タイトル30Hz上限 | 描画・背景ストリーミングの回数を抑える | 背景・雲・水・風・生き物を継続。経過時間で進める。60Hzの背景から30Hzになるため実機で滑らかさの確認が必要 |
| タイトルのチャンク生成を1件/描画までに | 一度の追加生成を抑える | 最終的な距離・チャンク品質は同じ。読み込み完了は遅くなる場合がある |
| タイトルのHUD更新を抑止 | 隠れたHUDや同じ文字列への書き込みを減らす | プレイ開始時は通常更新。操作・メニュースクロールは従来どおり |
| 生き物の共通インデックス＋種別オフセット | 頂点バッファ/属性設定を個体ごとに繰り返さない | 同じ頂点・同じ描画順序・同じ個体数。透明な影の順序も維持。モデル総量が16bit上限を超える場合は従来のバインド方式 |
| 遠距離ポーズ更新を30/20Hz上限に | 高価な関節計算を毎フレーム行わない | 45ブロック未満は従来頻度。遠方も毎描画で位置・カメラ座標を更新。画面外は既存どおり描画前に除外 |
| 骨行列の再利用 | 姿勢・位置・向きが同じならカメラ差分だけ補正 | 全再計算との数値比較テストあり。根元が移動すれば通常計算 |
| 既存AI距離段階の活用 | 負荷時・タイトルの遠方不可視個体のみ間隔を延長 | 近距離とモンスターの反応距離は従来どおり。最大ステップ0.3秒、余りの経過時間を保持。手動個体の削除ルールは不変 |
| 群れ中心の一時配列削除、プレイヤー移動判定共有 | 同じ情報の再計算とfilter配列生成を避ける | 探索対象、判定範囲、加算順は同じ。既存個体数上限を維持 |
| エッグのラベルを先に表示、画像は最大2個/コールバック | 初回の30種一括処理を分割 | 全種が直ちに選択可能。画像は順次現れる。閉じたら停止、再開・再表示は既存DOM/画像を使用 |
| ホットバー・選択エッグのDOM再利用 | 同じボタンを再生成しない | スロット、長押し、採掘/設置、飛行、タッチ操作は変更なし |
| 動的バッファの容量再利用 | 毎描画のbufferDataを、必要な容量拡張＋bufferSubDataへ | 同じ頂点を送る。実GPUのドライバによる性能差は未測定 |
| ブロック枠のジオメトリ再利用 | 同じ対象なら再配列生成・転送をしない | 枠は毎描画。対象変更時に更新 |
| GLプログラム/属性状態のキャッシュ | 不要なuseProgram・属性有効化/無効化を省略 | 描画パス・シェーダー内容は維持 |
| GPU/Worker寿命管理 | リンク済みシェーダーをdetach/delete、失敗時も解放。Worker URLをrevoke | 復旧時は古い状態を捨て、雲・GPUバッファ・Workerを再作成。古いWorker結果を拒否。保存処理には触れない |
| 自動解像度のヒステリシス | 低FPSが2窓継続してから低下、高FPSが3窓継続してから緩やかに復元 | 窓は約2秒。タイトル30Hzを負荷と誤判定しない。生成処理の多い窓は解像度低下を保留。手動画質プリセットを書き換えない |

インスタンシングは採用していない。現在は各個体のボーン配列をuniformで渡すため、ANGLE_instanced_arraysだけ追加しても個体ごとに異なる姿勢を1回で描けない。骨データの渡し方を大きく変更するより、WebGL 1の既存経路で重複設定を減らした。生き物のdrawElements回数そのものは減っていない。

地形生成、ワールド寸法、シード、描画距離、海・川・雲・植生のメッシュ/シェーダー、生き物の種類、プレイヤー速度、保存形式は変更していない。

## 同条件の比較

`perf.cjs` は乱数シード42・同じ旧地形ワールドで60体（2種交互）を近距離120フレーム＋遠距離120フレーム描く。別途タイトル120コールバック、エッグ初回、動的描画20回、同一ブロック枠60回を比較する。モックなのでGPU処理時間は含まれない。生き物の外観が画素単位で同一であることを証明するテストでもない。

| 指標 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 生き物バッファbind（240描画） | 14,400 | 240 |
| 生き物頂点属性設定 | 57,600 | 960 |
| 生き物drawElements | 14,400 | 14,400 |
| 遠距離ポーズ計算（120描画） | 7,200 | 2,058 |
| タイトル描画（120コールバック） | 120 | 60 |
| エッグを開く瞬間の同期アイコン生成 | 30 | 0（後で全30種を生成） |
| 動的bufferData（20描画） | 20 | 1 |
| 同一ブロック枠の転送（60描画） | 60 | 1 |

**処理回数の削減を確認した。実機FPSの改善率は未測定。** CPU時間は共有実行環境の競合で大きく変動したため、その割合を性能向上率として使わない。3回分の生データとindex.htmlのハッシュは [performance-mobile.json](performance-mobile.json) に収録した。

再現方法：

```sh
git show 34ba2c8e79c1429682f06d073ac52a0c95588a07:index.html > /tmp/jocraft-before.html
node perf.cjs /tmp/jocraft-before.html
node perf.cjs
node check.cjs
```

## ブラウザ上の測定

- `?bench`：従来の固定飛行・平均FPS・1% Low・最大フレーム時間に、ボクセル生成/メッシュ生成/LODメイン処理/Worker処理/AI更新の時間、描画命令数、表示生き物数を追加。保存禁止を維持。
- `?perf`：通常操作中に詳細計測を有効化。`Nisekura.performanceProfile` をコンソールから取得し、エッグ画面を開いた際のパネル構築/分割アイコン時間も確認できる。通常起動時は詳細集計を無効化。
- GPUメモリ見積もりに生き物モデル・共有インデックス・雲・海・動的バッファを追加。ドライバ内部やフレームバッファは含まない。旧版より集計範囲が広いため、旧表示値と直接比較しない。
- FPSは従来どおり冒頭3秒を除外。詳細処理カウンタは計測開始から全期間を集計する。

端末比較は同じ保存ファイル、シード、画質、画面方向、ブラウザ表示寸法、充電/低電力設定で行う。初回コンパイルを含む回とウォーム状態を分け、数回測る。10〜20分の連続探索後、バックグラウンド復帰、画面回転、WebGL復旧、配置80体、森林・水辺も確認する。

## 回帰確認と未検証

既存check.cjsを維持し、共有インデックスのオフセットと描画順、カメラ差分行列、距離別ポーズ、タイトル/通常/非表示の頻度、解像度ヒステリシス、エッグの分割/中断/再表示、DOM再利用、動的GPU容量、シェーダー解放、Worker URLと古い応答、雲のコンテキスト復旧、AI経過時間、ブロック枠キャッシュを追加した。

既存テストで地形・植生・水・雲の指紋、長距離移動のキャッシュ上限、30種/モンスター、80体の保存復元、タッチ/長押し/飛行/ズーム抑止、セーブ保護、ベンチによる保存禁止も確認する。

実機未検証：iPhone 16 / A16 iPadのFPS・発熱・電池消費・実GPUメモリ・長時間安定性、30Hzタイトルと遠距離ポーズの見え方、実WebGL画素比較、Safariのコンテキスト復旧。実行環境にブラウザ本体がなく、実ブラウザの画面テストは実施できていない。近景メッシュ1件や初期9チャンクの同期処理は残るため、高速飛行中の最大停止時間を保証するものではない。
