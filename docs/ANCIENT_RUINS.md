# v17 ANCIENT RUINS 実装設計

調査対象: `index.html`, `check.cjs`, `README.md`, `docs/SAVE_SYSTEM.md`。

- `height4` / `buildWonders` は既存の地形・絶景・水系を決定する。変更せず、遺跡は絶景の境界と出発地点を避けた低勾配の陸地に置く。
- `generateChunk` は樹木、`carveCaves`、`wonderVoxels`、`placeOres`、`placeChests` の順。terrain 11 だけ末尾に遺跡の純粋な箱状設計を適用する。`voxelChunk` は最後に保存済みの編集を適用するため建築が優先される。
- 遺跡の設計はシード、位置、向き、分岐側から決定し、全チャンクが同じ設計を参照する。地上の柱・梁は `tileMesh` と `lodWorkerSource` でも共通設計を使う。
- 既存の宝箱34→35の保存差分、`openChest`、`giveRare`、装備、防具、`hurtPlayer` を利用。ボスは既存の生き物モデル・描画・近接攻撃の対象に統合する。
- 仕掛けは踏むと永続的に開く扉と、宝箱で開く周回通路。入口への主経路を閉じない。中断・退却でボスのHP、扉、報酬の取得権は保存される。
- `version: 1` と保護付き同期保存を維持。新規ワールドのみ terrain 11。任意の `adventure.ruins` に発見、扉、守護者HP・撃破、報酬、攻略を記録する。旧地形1〜10の生成器はそのまま。
- 冒険記録はクラフト画面、案内は既存コンパスの追加1行。新たなタッチ操作ボタンは増やさない。ボスのHP表示は戦闘付近だけ。
- 遠方のダンジョンのボクセルは生成しない。近傍の守護者1体だけを更新し、既存の生き物共有バッファ、距離制限、描画負荷調整を利用する。

実行した検証・制限・操作はREADMEとSAVE_SYSTEMに記載する。

## 最終実装と確認

海岸は珊瑚の密集を避けて海底出口を選び、主階段と交差しない地下通路と一段ずつの階段で接続する。森は壁に葉がまとわり、シードの variant に応じて追加の小部屋を持つ。青い灯石・踏み石は既存の結晶の発光と光源ベイクを共有する。

v16コミットから固定した地形1〜10のバイト指紋、建築・装備・コインの再読込、全遺跡の実ブロック上の到達可能性、解除の保存、守護者の予兆・壁遮断・突進停止・撃破・報酬・再開、複数シードの海底階段、全画質のWorkerとメインスレッドのLOD一致を検証。描画スクリーンショットとブラウザ保存再開は `browser-check.cjs` で確認する。Safari実機のFPS・熱・長時間動作と手動タッチ攻略は未検証。
