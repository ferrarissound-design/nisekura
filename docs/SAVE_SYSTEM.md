# JOCRAFT2 セーブ保護

## 調査と互換性

従来は `nisekura-v1` の JSON を15秒ごとに直接上書きし、読み込みエラーを無視していた。新規作成はこのキーを削除する方式だった。ブロック差分は座標インデックスをキーにする Map で重複を防いでいたが、初期状態に戻しても記録が残った。建築はこの差分に含まれる。手動配置した生き物は `life.eggs`（最大80体）、自然発生の生き物は従来どおり再生成される。

今回も localStorage と `version: 1` を維持する。IndexedDB への移行は行わず、保存先変更によるリスクとバックグラウンド終了時の非同期書き込みを避けた。地形生成・描画・AI・ゲームバランスは変更していない。

## 保存キーと書き込み順序

| キー | 用途 |
| --- | --- |
| `nisekura-v1` | 現在のワールド |
| `nisekura-v1-backup` | 直前の正常なワールド、最大1件 |
| `nisekura-v1-protected` | インポート・新規作成前の退避、最大1件。自動保存では更新しない |

通常保存は、現在のキーが読み込み時と同じか確認 → スナップショット検証 → JSONシリアライズと再検証 → 現在の正常データをバックアップへコピー → 新しいデータを現在のキーへ書き込む。`setItem` の容量例外ではそのキーの旧値は維持される。バックアップ書き込みが失敗したら現在のキーには触れない。容量を空けるための自動削除はしない。

チェックサム付き JSON に `integrity`（FNV-1a、偶発的な破損検知用。署名・暗号ではない）と任意の `settings` を追加。従来フィールドは維持する：

- `seed`, `terrainVersion`, `worldWidth`, `worldHeight`
- `changes`: `[座標インデックス, ブロックID]` の配列（建築・掘削を含む）
- `inventory`, `creative`, `flying`, `player`, `yaw`, `pitch`, `dayTime`
- `life`: 出現設定、手動配置の種類・座標・向き・大きさ
- `settings`: 画質、HUD、鳴き声、選択スロット、選択スポーンエッグ

旧ファイルにチェックサムや設定は不要。寸法のない旧形式は64×64×40、地形バージョンなしはv1として読み、既存の座標変換を維持する。地形v1〜v8を受理し、未来の未知バージョンや不正なブロック・生き物は部分的に捨てず読み込みを停止する。元データは削除しない。読み込むだけでは保存を書き換えない。最初の保存時に旧JSONをそのままバックアップする。

## 復旧と切り替え

破損・読み取り失敗時は自動保存を止め、メニューに復旧案内を表示する。直前の正常セーブから復旧する場合もユーザー確認が必要。破損した元JSONは退避するので、書き出して調査できる。バックアップがないときも元データは残る。

インポートはファイルサイズ（最大12 MiB）、JSON、内容、チェックサムを検証してからシード・バージョン・差分件数を提示し確認する。現在の未保存の建築を含めて退避した後に置き換え、ページを再読み込みする。退避データを置き換える場合は追加確認する。復元先が退避データ自身の場合は、先にその内容を通常バックアップにも複製する。途中の失敗でも復元対象と現在の世界を残す。

「新しい世界」は書き出しを案内する確認 → 未保存状態も含めて退避 → 現在のキー削除 → 新しいシードで遷移する。キャンセルは書き込みゼロ。切り替えフラグが blur / visibilitychange / pagehide / 予約済み保存による古い世界の再保存を防ぐ。現在のキーがない場合にバックアップを自動復元しないため、新規作成後に旧世界が復活することもない。

「切り替え前の世界に戻す」で退避から復元できる。「退避データを書き出す」でJSONを端末に保存できる。保存・復元先は従来どおりブラウザとサイトのオリジン単位。別ブラウザ・別端末へはファイルで移す。

## 差分と保存頻度

読み込み時に差分の一括削減はしない。ユーザーが編集した座標だけ、現在の地形バージョンの `generateChunk` が生成した未編集ブロックと照合し、同じなら Map とチャンク索引から削除する。木、葉、隣接チャンクからの樹冠、水も同じ生成結果で比較する。比較用チャンクは最大4件（v6で約192 KiB）。生成アルゴリズム自体は不変。

15秒間隔は維持。通常は idle callback（未対応ならタイマー）へ保存を回し、重複予約と再入を抑止する。ブロックだけでなく座標・時刻・インベントリ・生き物・設定を含む前回成功スナップショットと比較して、同一ならストレージ書き込みを省略する。blur / visibilitychange / pagehide は同期保存する。

## 検証

`node check.cjs` に従来の回帰テストと保存専用テストを収録：旧64/256/2048幅、地形v1〜v8、建築再読込、編集を元に戻す操作、インベントリ・向き・飛行・時刻、80体の配置、動物・モンスター、設定、15秒保存・バックグラウンド保存、両書き込み段階の容量例外、破損・整合性不一致、バックアップ不在、インポート成功/失敗/キャンセル、退避交換失敗、新規作成保護、別タブ変更検出、Blobダウンロード、ファイルのサイズ/読取/JSONエラー。

Safari実機未検証：iPhone/iPadの「ファイル」保存先選択、ダウンロード後の実ファイル再選択、縦横画面でのメニュースクロール、バックグラウンド終了時のイベント配送、実ストレージ容量上限、数十時間規模の建築の保存時間・カクつき。

localStorageの同期シリアライズ・検証・書き込みは差分量に比例する。idle化しても大容量時の停止時間の上限を保証するものではない。容量が足りない場合は保存を拒否して既存の正常データを優先する。OS強制終了やブラウザデータ消去はイベントや同一端末内の退避だけでは防げないため、外部ファイルのバックアップを用意する。別タブ検出は書き込み直前の比較であり、複数タブ同時書き込みの完全なトランザクションロックではない。

今回の検証結果：変更前の回帰テスト、変更後の `node check.cjs`、追加の保存専用テストはいずれも終了コード0。最終追加のモンスター/設定/退避交換/非同期ファイル選択も保存専用テストで通過。`git diff --check` は問題なし。ヘッドレスブラウザでの画面検証は実行環境にChromium本体がなく実施できていない。

## 洞窟（terrainVersion 7）とセーブ

- 洞窟はシードから決まる**純関数**で、セーブには入らない（`terrainVersion: 7`、`seed`、変更したブロックだけが保存される）。同じシードなら毎回同じ洞窟になり、再読み込みで形は変わらない。
- 新しいブロックID（26青い結晶・27紫の結晶・28翠の結晶・29光ゴケ）は `changes` に保存できる。17〜25（植物の描画用に予約された番号）は検証で拒否する。
- v6以前のワールドは洞窟を生成しない（地形・ブロック・近景メッシュ・遠景タイルが従来とビット単位で同一であることをテストしている）。
- 洞窟内で壊した・置いたブロックは、地上と同じ `changes` に入り、地下⇔地上を行き来しても保たれる。


## 水中生態系（v12.0）とセーブ

水草・サンゴ・小石はチャンクのメッシュにだけ存在する装飾（シードと地形から毎回同じものが生成される）、魚は実行時だけの存在で、どちらもセーブに書き込まない。セーブ形式・`terrainVersion`・ブロックIDは変更なし（データ移行不要）。水中の編集は従来どおり `changes` に保存され、底を掘ればその列の装飾は消え、戻せば元の装飾が戻る。

## 珊瑚礁（v13.0）とセーブ

珊瑚礁の珊瑚・礁の岩・岩場は、v12.0の水草と同じくチャンクのメッシュにだけ存在する装飾で、新しい熱帯魚も実行時だけの存在。セーブ形式・`terrainVersion`・ブロックID・地形は変更なし（データ移行不要）。水中生態系のある生成バージョン7・8のワールドでは、既存のワールドの海にも珊瑚礁がそのまま現れる。

## 川の水（terrainVersion 8）とセーブ

v8では、川の弱い区間で川底が海面のすぐ上に残って「乾いた砂の川底」になっていた所を掘り下げ、水が入るようにした。新規ワールドだけがv8になり、既存のv7以前のワールドは地形・ブロック・近景メッシュ・遠景タイルが従来と完全一致のまま（テストで確認）。セーブ形式は変わらず、`terrainVersion: 8` を受理するようにしただけ。

## 絶景地形（terrainVersion 9）とセーブ

- v9では渓谷・滝・天然アーチ・奇岩・海底地形（珊瑚礁の丘・海底アーチ・海底渓谷・海底の崖）を追加した。どれもワールドシードから決まる**純関数**で、起動時にシードと元の地形から配置を一度だけ決め（約0.1秒）、セーブには入らない。
- 新規ワールドだけがv9になる。v8以前のワールドは地形・ブロック・近景メッシュ（地形・水・水中装飾）・遠景タイル・出発地点が従来と完全一致（`node check.cjs` で確認）。
- セーブ形式は変わらず、`terrainVersion: 9` を受理するようにしただけ。新しいブロックIDは無い（滝の裏の結晶・光ゴケは既存の26〜29）。
- 滝の水・天然アーチの岩を掘ったり置いたりした変更は、従来どおり `changes` に保存される。
- 「見つけた絶景」の記録はセーブではなく、端末の `localStorage` の `jocraft2-wonders-<シード>` に保存する（セーブ形式を変えないため。消えても絶景の発見通知がもう一度出るだけ）。

## サバイバル（v15.0）とセーブ

`version: 1` と地形バージョン（新規ワールドは引き続き `terrainVersion: 9`）は変更していない。サバイバルは地形を作り変えないため、生成バージョンは上げていない。追加したのは次の**任意フィールド**だけで、無いセーブは従来どおりに読む。

| フィールド | 内容 | 無い場合 |
| --- | --- | --- |
| `gameMode` | `'survival'` / `'peaceful'` / `'creative'` | `creative: true` → クリエイティブ、それ以外 → ピースフル（従来の「素材集め」と同じ遊び方。サバイバルへ強制変更しない） |
| `health` | 0〜20（ハート10個） | 20 |
| `items` | `woodSword` / `stoneSword` / `ironSword` / `apple` の個数 | すべて0 |
| `defeated` | 倒したモンスターの数（序盤の難易度緩和に使う） | 0 |
| `settings.hotbar` | ホットバーの選択位置（0〜17） | `settings.selected` を使う |

- **旧リリースとの互換**：`creative` は `gameMode` と常に同期して保存する。旧リリースは追加フィールドを無視するので、サバイバル／ピースフルの世界は「素材集め」として開ける。
- **ホットバー9番目以降の保存不具合を修正**：旧リリースの検証は `settings.selected` が0〜7でないとセーブ全体を拒否していたため、葉・雪など9番目以降のスロットを選ぶと保存が毎回失敗していた。`selected` には0〜7（範囲外は0）を、実際の位置は `settings.hotbar` に保存する。旧リリースでも読める形のまま修正した。
- **体力0で保存された世界**（復活画面のまま終了）は、読み込み時に出発地点・体力満タンで再開する。持ち物は失わない。
- 剣・りんごは `inventory`（ブロックIDのみ受理）ではなく `items` に入れる。旧リリースの検証が未知のブロックIDを拒否してセーブを開けなくなるのを避けるため。未来のリリースが追加する未知のアイテム名は、値が0以上の整数なら受理して無視する。
- 検証で拒否するもの：未知の `gameMode`、範囲外の `health`、配列や負の値の `items`、整数でない `defeated`。拒否時は従来どおり読み込みを停止し、元データを保護する。
- 自然発生のモンスターや矢は保存しない（従来どおり）。スポーンエッグで置いたゾンビ等は `life.eggs` に保存され、サバイバルでは敵として振る舞う。

## 鉱石・宝箱（terrainVersion 10）と装備（v16.0）

- 新規ワールドだけが `terrainVersion: 10`。鉱石と宝箱はシードとチャンクだけで決まる**純関数**で生成され、セーブには入らない。v9以前のワールドは地形・ブロックが完全に同じ（同じシードのv9とv10の差は「石→鉱石」「空気/水→宝箱」だけであることをテスト）。
- 新しいブロックID：30石炭鉱石・31鉄鉱石・32金鉱石・33ダイヤモンド鉱石・34宝箱・35開いた宝箱。`changes` に保存できる。36以上は拒否。`terrainVersion` は1〜10を受理し、11以上は拒否。
- **宝箱を開けると** その位置が35（開いた宝箱）に変わり、通常の `changes` として保存される。生成される34とは別の値なので、再読み込みしても同じ宝箱から二度は取れない。プレイヤーが置いた・壊したブロックは `changes` が優先されるので、宝箱が勝手に戻ることはない。中身は宝箱の座標と種類から決まり、乱数の取り直しはできない。開封直後に保存を予約する。
- `items` に任意フィールドを追加：`diamondSword`、`woodPick` `stonePick` `ironPick` `diamondPick`、`leatherArmor` `ironArmor` `diamondArmor`、素材 `coal` `iron` `gold` `diamond` `leather`、コレクション `coin` `crystal` `dragonEgg`、開けた宝箱の数 `chests`、初発見のビット `found`。すべて0以上の整数（既存の検証規則のまま）。旧セーブにはないので0として始まる。旧リリースは知らないキーを無視する。
- `health` は防具で半ハート単位（例 17.5）になることがある（従来から実数を許可、0〜20）。
- v9以前のワールドで遊んでも新しいブロックIDは保存されない（鉱石・宝箱が生成されないため）ので、旧リリースでも開ける。v10のワールドは旧リリースでは未対応バージョンとして読み込みを止め、元データを保護する。

## 古代遺跡（terrainVersion 11 / v17.0）

- **新規ワールドだけ**が地形11になる。地形1〜10の生成器には遺跡を適用しない。v16のコミット `a40d15d` から採取したチャンクのバイト指紋を `docs/v16-terrain-fixtures.json` に固定し、旧世界の建築・装備・コインを保存後に読み直すテストを追加した。
- 保存形式は引き続き `version: 1`。地形11とブロック36古代の石材・37苔むした石材・38灯石・39石扉・40踏み石を受理する。地形12以上・未定義ブロックは保存元を保護して拒否する。地形11はv16以前のアプリでは開けない（未知バージョンとして停止）。
- 任意フィールド `adventure.ruins` はシードで決まる遺跡ID `r0`〜`r11` をキーに、`discovered`（発見）、`gate`（踏み石）、`secret`（宝箱の周回路）、`hp`（守護者の残HP、0〜96）、`guards`（小部屋の敵の撃破ビット）、`defeated`（守護者撃破）、`claimed`（宝物取得）、`cleared`（攻略）を保存する。旧セーブには不要。旧世界のスナップショットには追加しない。
- 扉は一度開けば閉じない。保存差分がなくても解除済みの扉を再現した後に、建築・掘削の保存差分を適用する。開ける時も生成された石扉だけを除去し、プレイヤーの建築を消さない。入口への階段は施錠しない。サバイバルでは解除前の石扉（正面は `gate`、横の隠し通路は `secret` が未設定の間）を採掘で壊せない（`sealedDoor` / `doorBlocked`、`mine()` と `breakBlock()` の両方）。判定は遺跡の扉のセルと保存済みフラグだけを見るので、保存形式は変わらず、旧ワールド・クリエイティブ・遺跡外の39番ブロックには影響しない。
- 宝箱は既存の34→35の差分で一度だけ開く。守護者の宝箱は `claimed` も照合し、宝箱を再配置しても再取得できない。報酬・攻略・開封は同じスナップショットに入る。新アイテム `ancientSword` と `eggClue` は既存の `items` の非負整数を利用する。
- ピースフル／クリエイティブでは戦わずに宝物を受け取れる。攻略数は増えるが、守護者撃破は記録しない。サバイバルに戻しても宝物は増えない。
- 15秒保存、背景遷移時の同期保存、チェックサム、直前バックアップ、切り替え前退避、容量不足・破損・別タブ保護は従来どおり。発見・解除・撃破・開封は既存の保存予約を使う。ボスの残HPは被弾時に更新し、通常保存と背景保存で保存する。
- 自然発生の敵や守護者の姿勢・攻撃タイマーは保存しない。戻ると守護者は部屋の中央から登場し、残HPと撃破済み状態を引き継ぐ。竜の孵化・育成は v18.0（下記）で追加。

## ドラゴン（v18.0）

- 地形生成は変更しない。地形1〜11の生成結果と保存差分（`changes`）はそのまま。巣と卵はブロックではなく生き物モデルなので、`changes` に何も追加しない。
- 保存形式は引き続き `version: 1`。任意フィールド `dragon` を追加：`stage`（`none`/`egg`/`baby`/`young`/`adult`）、`name`（12文字以下）、`warmth`（ぬくもり秒）、`growth`（成長ポイント）、`joy`（0〜100）、`follow`、`riding`、`x`/`y`/`z`/`yaw`（巣またはドラゴンの位置）、`fed`/`pets`/`flights`/`sense`（非負整数）、`flyDist`。ドラゴンも卵も無く、ぬくもりも0なら保存しない（旧世界のスナップショットは変わらない）。
- 検証：段階・型・範囲（座標は世界内、高さは地形の高さ内）を確認し、`riding` は成体だけ許可する。不正値は既存どおり保存元を保護して拒否する。旧セーブ（`dragon` なし）はドラゴンなしで開く。古いアプリは未知のフィールド `dragon` を無視して開ける（そのアプリで保存するとドラゴンは失われる）。
- 増殖防止：卵を巣に置くと `items.dragonEgg` が1減って `stage: egg` になり、持ち上げると逆になる（同じスナップショットで一度に変わる）。ドラゴンか巣があると次の卵は置けない。孵化は `egg` → `baby` の一度だけ。新しい `items.eggChests`（開けた伝説の宝箱の数）は既存の `items` の非負整数を利用する。
- 飛行中に保存した場合は `riding: true` を保存し、再開時にドラゴンがプレイヤーの真下にいれば飛行中から続ける。そうでなければ徒歩で再開する。ドラゴンの姿勢・速度・AIのタイマーは保存しない。
- 15秒保存、背景遷移時の同期保存、チェックサム、直前バックアップ、切り替え前退避、容量不足・破損・別タブ保護は従来どおり。孵化・成長・巣の設置と持ち上げは既存の保存予約を使う。

## 建築パーツ（v19.0）

- 地形生成は変更しない。地形1〜11の生成結果はそのまま。保存形式は引き続き `version: 1`。新しいフィールドは追加していない。
- 建築パーツは **向き・状態ごとに別のブロックID** にして、既存の `changes`（座標インデックス→ブロックID）にそのまま保存する。チャンクのボクセルは1マス1バイトのまま、別の保存領域や移行処理は不要。

  | ID | ブロック | 内容 |
  | --- | --- | --- |
  | 41〜44 | 木の階段 | 上る向き 41 +z / 42 +x / 43 −z / 44 −x |
  | 45〜48 | 石の階段 | 同じ順 |
  | 49 / 50 | 窓 | ガラス面が x 方向に広がる / z 方向に広がる |
  | 51〜66 | 木のドア | 51 + 向き×4 + 開いている×2 + 上半分（向きは階段と同じ順） |
| 67〜82 | 木のドア（右ちょうつがい・v19.1） | 両開きの2枚目。67 + 向き×4 + 開いている×2 + 上半分 |
| 83〜90 | さかさまの階段（v19.2） | 83〜86 木 / 87〜90 石（41〜48 に 42 を足した番号、向きの順は同じ） |

- 持ち物（`inventory`）は各グループの先頭ID（41 木の階段・45 石の階段・49 窓・51 木のドア）の個数。壊すとどの向き・状態でも先頭IDに戻る。ドアは上下2マスで1個。
- 検証：`changes` と `inventory` は 41〜90 を受理し（v19.0 は 66、v19.1 は 82 まで）、91以上・未定義のIDは従来どおり保存元を保護して拒否する。17〜25（植物の予約）の拒否も従来どおり。`settings.hotbar` は 0〜24（ホットバー25枠）。
- ドアの開閉はIDの差し替え（例 51⇄53）なので、開けたまま・閉めたままの状態がそのまま保存される。開閉のアニメーションの途中状態は保存しない（保存されるのは開閉後の状態）。
- 旧セーブ（パーツなし）は変更なしで開き、建築パーツの持ち物は0から始まる。古い遺跡の封印扉（39）・踏み石・宝箱（34/35）・ドラゴンの保存は別のIDとフィールドなので影響しない。
- 互換の注意：建築パーツを1つでも持つ・置くと、そのセーブは v18 以前のアプリでは未定義のブロックIDとして読み込みを止める（元データは保護され、消えない）。v17 の地形11・ブロック36〜40 と同じ扱い。
- 15秒保存、背景遷移時の同期保存、チェックサム、直前バックアップ、切り替え前退避、容量不足・破損・別タブ保護は従来どおり（設置・破壊・開閉は既存の `dirty` と保存予約を使う）。
- v19.1：角の階段は保存しない（となりの階段から毎回同じ形が決まる）。両開きの2枚目（67〜82）を置いたセーブは v19.0 のアプリでは未定義IDとして読み込みを止める（元データは保護）。
- v19.2：さかさまの階段（83〜90）を置いたセーブは v19.1 以前のアプリでは未定義IDとして読み込みを止める（元データは保護）。持ち物は従来どおり先頭ID（41・45）の個数で、さかさまのIDは `inventory` に入らない。

## v20 ハーフブロック

`version: 1`、地形バージョン、座標の符号化、チェックサム、バックアップ、チャンクの `Uint8Array` は変更しない。追加IDだけで素材と上下状態を表す。

| 素材（既存ID） | 下付き | 上付き | 2枚重ね | 持ち物ID |
| --- | --- | --- | --- | --- |
| 木材（7） | 91 | 92 | 93 | 91 |
| 石（3） | 94 | 95 | 96 | 94 |
| 原木（4） | 97 | 98 | 99 | 97 |
| レンガ（8） | 100 | 101 | 102 | 100 |
| 白樺（13） | 103 | 104 | 105 | 103 |
| 古代の石材（36） | 106 | 107 | 108 | 106 |

- 設置は持ち物を1個消費する。同じ素材の上下が揃うと同じセルを2枚重ねIDへ置き換える。2枚重ねは高さ1の形状だが、通常素材IDへ変換しないため上下を別々に回収できる。片側を壊すともう片側のIDへ変わり、持ち物が1個増える。
- `changes` は0〜108の定義済みIDを受理する。植物の予約ID17〜25と未定義ID109以上は拒否する。通常の操作では `inventory` に上付き・2枚重ねIDを入れない。
- ホットバーの末尾に6枠を追加する（0〜30）。既存25枠の順番を保ち、旧セーブの選択位置・持ち物・建築物・地形に変更はない。
- 新版は既存セーブを読み込める。ハーフを置く・持つ、または追加枠を選択して保存したセーブは、v19.2以前のアプリでは未対応のID／選択枠として保護される。古いアプリへの逆方向の互換は保証しない。
- 18状態の保存・チェックサム検証・再起動復元と、持ち物・選択枠の復元を `check.cjs` で確認する。


## v20.1 ホットバー表示の整理

保存形式は変更しない（`version: 1`、新しいフィールドなし）。

- `settings.hotbar` は従来どおり全31枠（0〜30）の位置。サバイバル／ピースフルでは持っていない枠を画面上で隠すだけで、枠の順番と番号は変わらない。クリエイティブは全枠を表示する。
- 選択中の枠は0個でも表示を保つため、0個の枠を選んだまま保存したセーブも、読み込み後に同じ枠が選ばれて見える。
- 範囲外の `settings.hotbar` は従来どおり検証で拒否し、選択位置が枠の外を指すことはない。`settings.hotbar` がない旧セーブは `settings.selected` を使う。
- 数字キー1〜8は「表示中のn番目の枠」を選ぶ（クリエイティブは従来と同じ）。保存される値は枠の位置のまま。
